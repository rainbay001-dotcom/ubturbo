▶ 写入路径（内存分配 / 页面迁移）
STEP 01
openclaw 分配内存
browser 进程请求分配新内存页，内核 mm 介入。smap 记录分配时间戳与初始热度评分。
malloc / mmap
›
STEP 02
初始置于 L1 DRAM
新分配页面默认置于本地 DRAM，保障初始访问延迟最优。smap 开始追踪 PTE Access Bit。
L1 驻留
›
STEP 03
热度衰减 → 迁移至 L2
smap 周期扫描，检测 Tab 切换或页面长期未访问，触发 L1→L2 异步迁移。更新页表映射至 UB 借用内存。
UB RDMA 搬运
›
STEP 04
继续衰减 → 归档 L3
L2 中长期不访问的页面进一步降级至 NVMe，以 swap 语义写入 NVMe 设备，释放 L2 空间。
NVMe 写入
›
STEP 05
超分空间释放
冷数据归档后，L1 DRAM 空间释放，可供新 VM 分配。整机装机密度提升，超分比达到目标。
超分比 ↑ 2-3×
▶ 读取路径（Tab 激活 / 数据预取）
STEP 01
Tab 激活 / 内存访问
openclaw 切换到后台 Tab 或访问已迁移内存，触发缺页异常（Page Fault），进入 smap 处理流程。
Page Fault 触发
›
STEP 02
查询 smap 位置索引
smap 查询内存位置索引，确认目标页面当前驻留在 L2 (UB) 还是 L3 (NVMe)，决定 Fetch 路径。
位置查找 O(1)
›
STEP 03
L2/L3 → L1 Prefetch
触发异步 DMA/RDMA 操作，将目标页面从 L2 或 L3 搬运至 L1 DRAM。同时 Prefetch 相邻页面。
DMA 搬运
›
STEP 04
页表更新 · 返回数据
更新 VM 页表映射至新 L1 地址，解除 Page Fault，openclaw 访问恢复正常。全程对业务透明。
透明恢复
›
STEP 05
热度更新 · 驻留 L1
访问后 smap 更新热度评分，频繁访问的页面稳定驻留 L1，确保 openclaw 前台 Tab 交互延迟满足 SLA。
SLA 保障
